# SHARED_FOLDER_AUTOMATION.md — 공유폴더 기반 백서 자동 생성 방안

> **구조 안내**: 이 문서는 **설계**다. 지금 이 Coworkai 세션에서 실시간으로 동작시키는 게
> 아니다 — 대화형 세션은 상시 폴더 감시 권한이 없다. 실제 자동화는 사내 시스템 확인
> (운영 위치 미확정, `STRUCTURE_DECISION_OPTIONS.md` 참조) 이후, `ROADMAP.md` M2 단계에서
> 실행 방식을 정한다. 이 문서는 그때 쓸 설계를 지금 미리 잡아둔다.

---

## 목표

부서원이 공유폴더에 파일(음성전사/스크린샷/텍스트 메모 등)을 놓기만 하면, 별도로 Topic Card
양식을 열지 않아도 (a) 그 파일이 카드로 구조화되고 (b) 백서 폴더 구조와 자연스럽게 연결되게
한다. `WRITING_METHODOLOGY.md` D절(카드 입력 처리 절차서)을 사람이 매번 수동 실행하는 대신,
**폴더 규칙으로 자동 트리거**하는 게 이 문서의 핵심이다.

## 두 가지 자동화 축

### 축 1 — 파일을 놓으면 주기적으로 읽어 카드화

**동작 개념**:
```
[공유폴더/INBOX/] ← 부서원이 파일을 여기 놓음
        ↓ (주기적 확인)
[D절 절차 실행] (D-01~D-05, WRITING_METHODOLOGY.md)
        ↓
[공유폴더/PROCESSED/] + TOPIC_REGISTRY.yaml 후보 등록(status=candidate만, 자동 승격 없음)
```

**실행 주체 후보** (사내 시스템 확인 후 택1, 지금 결정 안 함):
- 사람이 정기적으로(예: 매주 1회) INBOX를 열어 Claude 세션에 붙여넣고 D절 실행 → 가장 낮은
  기술 부담, v1 직후 바로 가능
- 사내 자동화 도구(있다면)로 폴더 변경 감지 → AI API 호출 → 사내 시스템 확인 전에는 불가
- 정식 M2(입력 전처리 자동화, TOPIC-0002) 도구가 만들어지면 그걸로 대체

**v1 직후 가장 현실적인 방식**: "주기적 사람 트리거 + D절 수동 실행"이다. 완전 자동(폴더
감시 데몬 등)은 M2 이후로 미룬다 — 지금 만들면 과설계(외부 감사 BLOCKER-1 재발 위험).

### 축 2 — 폴더 구조를 백서 폴더 구조와 동기화

**원칙**: 공유폴더 구조가 `cowork-runtime/projects/part_work_whitepaper/`의 논리 구조를
그대로 반영해야, 나중에 Git으로 옮기든 다른 시스템으로 옮기든 매핑이 쉽다.

**제안 매핑** (사내 공유폴더 최상위 아래):

```
공유폴더/PartWorkWhitepaper/
  INBOX/              ← 부서원이 원본(텍스트/전사/스크린샷) 놓는 곳
  PROCESSED/          ← D절 처리 후 원본 보관(감사 추적용)
  CARDS_PENDING/      ← 카드 초안, 아직 사람 확인 전 (D-04/D-05 상태)
  CARDS_CONFIRMED/    ← 확인 완료, Registry 등록 대상
  REFERENCE/          ← 이 안내 문서들의 사본(TOPIC_CARD_TEMPLATE 등, 읽기 전용)
```

이 구조는 `TOPIC_REGISTRY.yaml`의 `status` 값(candidate/under_review/…)과 폴더 위치가
대응되도록 설계됐다 — 파일이 어느 폴더에 있는지만 봐도 어느 상태인지 알 수 있게.

## Export Safety와의 연결 (필수)

공유폴더에 놓인 원본은 **PROCESSED로 옮기기 전에** `EXPORT_SAFETY_CHECKLIST.md`를 반드시
거친다 (D-02와 동일). 자동화가 이 단계를 건너뛰게 설계되면 안 된다 — 축 1의 파이프라인
어디에 두든, "Export Safety 확인 전에는 다음 단계로 안 넘어간다"는 게 유일한 하드 룰이다.

## v1 범위와의 관계

이 문서는 **설계까지만 v1**이고, 실제 폴더 생성·자동화 실행은 v1 범위 밖이다
(`STRUCTURE_DECISION_OPTIONS.md`의 "사내 시스템 확인 후 만들 것" 항목과 동일 선상). 이유:

- 운영 위치(공유폴더 vs Git vs 문서시스템) 자체가 아직 미확정
- 폴더 자동 감시는 사내 권한·도구 확인이 선행돼야 함

**따라서 지금 할 수 있는 건 "이 설계를 문서로 남기는 것"까지다.** 사내 시스템 확인 완료 후,
`ROADMAP.md` M0(원자화) 완료 조건(부서 회의 통과) 충족 시 이 설계를 실행 단계로 옮긴다.

## TOPIC_REGISTRY 연동 (참고용, 신규 등록 아님)

이 자동화 방안 자체도 하나의 Topic 후보다. 다만 지금은 **설계 문서로만** 두고 Registry에는
아직 등록하지 않는다 — TOPIC-0002(입력 전처리 자동화)와 범위가 겹치므로, 사내 시스템 확인 후
TOPIC-0002를 이 설계 기준으로 구체화하거나 별도 Topic으로 분리할지 그때 판단한다.

## 이 문서를 갱신하는 법

- 사내 시스템 확인 결과가 나오면 "실행 주체 후보" 절의 택1을 확정하고 이 문서 상단 안내를
  "설계"에서 "실행 중"으로 바꾼다.
- 폴더 구조가 실제 운영 중 안 맞으면(예: PROCESSED가 너무 커짐) 이 문서에 먼저 반영하고
  실제 폴더를 나중에 바꾼다 — 문서가 먼저, 실물이 나중.
