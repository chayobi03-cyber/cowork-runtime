# ROADMAP.md — 마일스톤 및 관계 지도

> **구조 안내**: 이 문서는 v1 범위 밖 항목(TOPIC_REGISTRY의 `hold` 상태 등)을 시간순
> 마일스톤과 항목 간 관계(지식그래프)로 관리한다. v1 실행 작업은 여기 안 담는다 —
> 그건 `ATOMIC_PLAN.md`(실행 단위)와 `TOPIC_REGISTRY.yaml`(개별 업무 단위)이 담당한다.
> 이 문서는 "지금 당장 할 일"이 아니라 "나중에, 어떤 순서로, 무엇에 의존해서" 할지를 담는다.

## 마일스톤 (시간순 단계)

각 단계는 이전 단계의 산출물을 전제로 한다. 단계를 건너뛰지 않는다.

### M0 — 원자화 (v1, 진행 중)

업무를 Topic Card 단위로 원자화하고, AI가 접근·검색·수정·재사용 가능한 구조를 만든다.
**지금 여기 있음.** 완료 조건: 부서 회의 통과 + 실제 파트원 카드 입력 몇 건 확인.

### M1 — 지식그래프 연결 (v1 이후)

M0에서 쌓인 Topic Card들 사이의 관계(어느 업무가 어느 업무와 데이터를 주고받는지, 어느 Role이
여러 Topic에 걸치는지)를 명시적으로 연결한다. 아래 "지식그래프" 절이 이 단계의 스키마 초안이다.
착수 조건: Topic이 실제로 5개 이상 등록되어 관계 파악이 의미 있어지는 시점.

### M2 — 입력 전처리 자동화 (TOPIC-0002)

음성 전사, 화면녹화 프레임 추출 등 사람이 지금 수작업으로 해야 하는 전처리 단계를 도구화한다.
`TOPIC_REGISTRY.yaml`의 TOPIC-0002(hold)가 이 단계의 대상. 착수 조건: M0 회의 통과 + 별도
프로젝트 착수 승인.

### M3 — 업무 효율화 Agent 생성 (장기 목표)

M0~M2에서 만들어진 원자화된 구조·관계·자동 입력 파이프라인을 기반으로, 실제로 반복 업무를
대신 처리하는 agent를 만든다. 이건 v1의 산출물이 아니라 v1이 가능하게 만드는 최종 목표다.
착수 조건: M1 지식그래프가 실제로 몇 개 Topic 간 연결을 담고 있고, M2 전처리 도구가 최소
1건 이상 검증된 이후.

```
M0(원자화, 지금) → M1(관계 연결) → M2(입력 자동화) → M3(agent 생성)
```

## 지식그래프 (항목 간 관계 스키마 초안, M1에서 실사용)

v1 단계에서는 아직 Topic이 적어(TOPIC-0001, TOPIC-0002 둘뿐) 그래프로 다룰 실익이 없다.
아래는 **M1 착수 시 쓸 스키마 초안**만 미리 잡아둔다 — 지금 채우지 않는다.

```yaml
# 초안 스키마 예시 (M1 착수 전까지 미사용)
nodes:
  - id: TOPIC-xxxx
    type: topic
  - id: ROLE-xxxx      # M1 이후 필요 시 도입, v1에는 없음
    type: role

edges:
  - from: TOPIC-xxxx
    to: TOPIC-yyyy
    relation: "출력을 입력으로 사용함" # 예: 데이터 흐름 의존관계
  - from: TOPIC-xxxx
    to: ROLE-xxxx
    relation: "이 역할이 주로 수행함"
```

**M1 착수 시 결정할 것 (지금 결정 안 함)**: 이 그래프를 별도 파일(`KNOWLEDGE_GRAPH.yaml`)로
뺄지, TOPIC_REGISTRY.yaml에 `related_topics` 필드로 흡수할지는 Topic 개수가 실제로 5개를
넘는 시점에 판단한다 (5절 사다리 원칙과 동일 패턴).

## 이 문서를 갱신하는 법

- 새 마일스톤이 필요해지면 M4, M5로 이어 붙인다 — 기존 M0~M3 순서/조건은 안 건드린다.
- 특정 마일스톤의 착수 조건이 실제로 충족되면, 이 문서가 아니라 `CLAUDE_MAINTENANCE_LOG.md`에
  "M1 착수함" 식으로 기록하고, 이 문서의 해당 마일스톤 옆에 "(착수: 날짜)"만 추가한다.
- 지식그래프 스키마는 M1 착수 전까지 초안 그대로 두고 실제로 채우지 않는다.
