# WP-0003 MVP Plan: CST/S-parameter 이상탐지

작성일: 2026-07-14 · Plan-first 승인 대기 · 관련: RESEARCH_SUMMARY.md(커밋 b87125f), 냉정audit(2026-07-14)

## 1. 목적
1인 로컬 CST 시뮬레이션 결과(S-parameter)의 수작업 그래프 검토를, MAD+Isolation Forest 이중
스크리닝으로 보조한다. 정상으로 판단되는 대다수를 자동으로 걸러내고, 의심스러운 소수만 수작업
검토 대상으로 남긴다.

## 2. 배경
딥리서치 4개 스레드 교차검증 + 합성 데이터 실행검증 완료(이상 3건 100% 탐지, 정상 20건 오탐 0건).
2026-07-14 냉정audit(섹션1 14항목) 결과: BLOCKER 없음, MAJOR 다수 — 핵심 원인은 "실제 CST 데이터로
는 아직 한 번도 안 돌려봤다"는 것. 이 Plan은 그 공백을 메우는 것이 목적이다.

## 3. 입력 자료
창엽님이 보유한 실제 CST 결과 S2P 파일 중:
- 과거 "정상"으로 판단했던 시뮬레이션 결과 10~20개
- (있다면) 과거 실제 문제가 됐던 사례 파일 — 없으면 이번 단계에서는 정상군만으로 오탐률만 확인

**관심 주파수 대역 (2026-07-15 확정)**: 1차 30MHz~1GHz, 2차 1GHz~3GHz, 3차 3GHz~10GHz.
`bands = [(0.03, 1.0), (1.0, 3.0), (3.0, 10.0)]` (GHz)로 고정해서 feature 추출.

## 4. 작업 범위
- feature 추출 함수(min/max/mean/median/std/percentile/area/peak/band별 통계) — RESEARCH_SUMMARY.md
  검증된 코드 그대로 사용
- MAD + Isolation Forest 스코어링 함수
- CSV 출력(score, flag)
- **실제 데이터 10~20건으로 1차 검증** (이 항목이 이번 Plan의 핵심 — 냉정audit MAJOR-4/5/9 해소용)

## 5. 제외 범위
- plotly 대시보드/리포트 UI (2단계 확장 후보)
- 실시간 처리, CST 자동 연동
- 클라우드/서버 인프라
- CISPR 등 EMC 표준 한계치 적용 (Research→Main 격리 원칙 유지, 4.10)

## 6. 기대 산출물
- 실행 가능한 `.py` 스크립트 (저장소 반영 — 지난 audit에서 지적된 "코드블록만 있고 실행파일 없음"
  traceability 문제 해소)
- 실제 데이터 실행 결과 CSV
- run_report (오탐/미탐 여부, 사용한 파라미터 기록)

## 7. 검증 기준
- 실제 정상 시뮬레이션 10~20건 입력 시 오탐률이 설정 파라미터(contamination=0.05)와 크게 어긋나지
  않는지
- 과거 실제 문제 사례가 있다면 그것이 flag=True로 잡히는지
- "그럴듯함" 수준이 아니라 이진 판정(탐지/미탐지, 오탐 개수)으로 기록

## 8. 리스크 점검 항목
- 설계군(보드rev, 조건)이 섞이면 오탐 폭증 — 파일명 규칙으로 최소 구분 필요
- 합성 데이터와 실제 데이터의 분포 차이로, 검증됐던 임계치(k=3.5, contamination=0.05)가 실데이터엔
  안 맞을 가능성이 큼 — 이번 단계에서 재튜닝 전제
- 파일명 규칙을 안 지키면 다음 세션에서 재현 불가
- **(2026-07-15 실제곡선 재검증에서 발견) MAD 방식은 저분산·이산적 feature(n_peaks,
  max_peak_prominence)에 취약해 오탐률이 최대 20%까지 발생할 수 있음** → MAD 계산에서 이 두
  feature를 제외하는 수정판 적용(RESEARCH_SUMMARY.md 섹션6 참조). 그래도 완전히 해결되지 않아
  Isolation Forest를 주 판정, MAD는 보조 참고용으로 운용 권장
- **입력 파일의 실제 주파수 범위가 관심 대역(30MHz~10GHz)과 안 겹치면 band별 feature 전체가 NaN**
  이 되어 StandardScaler 경고 발생 — 실행 전 주파수 범위 겹침 여부 사전 확인 로직 필요
