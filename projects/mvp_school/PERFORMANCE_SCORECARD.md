# PERFORMANCE_SCORECARD.md

## 1. 목적

MVP School의 성능은 아이디어가 회사 PC에서 실행, 검증, 수정 가능한 MVP로 졸업할 수 있는 정도로 판단한다.

각 항목은 100점 만점으로 평가하고, 최종 점수는 가중 평균으로 계산한다.

사람은 직접 반복 계산하지 않는다. AI가 점수 초안을 산정하고, 사람은 Approve / Reject / Needs changes만 판단한다.

## 3. 점수 해석

| 최종 점수 | 판정 | 의미 |
|---:|---|---|
| 90~100 | Strong Graduate | 바로 회사 PC로 넘겨도 됨 |
| 80~89 | Graduate | 경미한 보완 후 졸업 가능 |
| 70~79 | Needs changes | 보완 후 재심사 |
| 50~69 | Hold | 구조 재정리 필요 |
| 0~49 | Reject | 현재 MVP School 대상 아님 |

단, BLOCKER가 있으면 점수와 무관하게 졸업 불가다.

BLOCKER가 있으면 최종 점수는 최대 69점으로 제한한다.

## 4. BLOCKER Gate

다음 중 하나라도 있으면 졸업 불가다.

1. 목적과 문제 정의가 불명확하다.
2. 실행 방법이 없다.
3. 테스트 방법이 없다.
4. evidence가 없다.
5. 사람이 반복 작업을 직접 해야 한다.
6. 기밀 가능 정보가 외부 입력용 문서에 포함되어 있다.
7. 회사 PC에서 이어받을 수 없다.
8. MVP 범위가 너무 커서 작게 검증할 수 없다.
9. 실패 원인 분리가 불가능하다.
10. Plan 없이 schema/config/metadata/runner/queue/evidence 구조를 바꾸려 한다.

## 5. 항목별 채점 기준

### 5.1 문제/효과 명확성 — 100점

| 세부 기준 | 점수 |
|---|---:|
| 문제를 한 문장으로 설명 가능 | 20 |
| 반복 업무/비효율이 명확 | 20 |
| 기대 효과가 시간 절감/오류 감소/검증성/추적성 중 하나 이상 | 25 |
| 사용 대상이 명확 | 15 |
| 성공/실패 판단 기준 있음 | 20 |

### 5.2 MVP 범위 절단 성능 — 100점

| 세부 기준 | 점수 |
|---|---:|
| MVP 범위가 작고 명확 | 25 |
| 제외 범위가 명확 | 25 |
| 하나의 핵심 문제만 다룸 | 20 |
| 현재 범위와 backlog가 분리됨 | 20 |
| 과확장 위험 낮음 | 10 |

통합 MVP 점수 판단:

| 통합 수준 | 점수 판단 |
|---|---:|
| 기존 모듈을 얇게 연결하고 E2E smoke test만 함 | 90~100 |
| 일부 adapter/runner만 추가함 | 80~89 |
| 2~3개 모듈의 수정이 같이 필요함 | 60~79 |
| 모듈 구현 + 통합 + UI/DB까지 같이 함 | 40~59 |
| 플랫폼 전체를 한 번에 만들려 함 | 0~39 |

### 5.3 AI 실행 가능성 — 100점

| 세부 기준 | 점수 |
|---|---:|
| 입력/출력이 명확 | 20 |
| 작업 단위가 작음 | 20 |
| Plan-first 가능 | 20 |
| 기존 구조 재사용 가능 | 15 |
| Codex/Claude Code 등에 전달 가능한 형태 | 15 |
| 사람 반복 작업 없음 | 10 |

### 5.4 검증/evidence 가능성 — 100점

| 세부 기준 | 점수 |
|---|---:|
| 테스트 방법 명확 | 20 |
| 정상 케이스 있음 | 15 |
| 오류/malformed 케이스 있음 | 15 |
| 자동 검증 가능 | 15 |
| run_report/evidence 생성 가능 | 20 |
| known limitation 기록 가능 | 15 |

통합 MVP 추가 기준:

1. 모듈별 입출력 contract가 있는가
2. 실패한 모듈을 run_report에서 식별할 수 있는가
3. end-to-end smoke test가 있는가
4. 각 모듈의 내부 검증과 통합 검증이 분리되어 있는가

### 5.5 Trajectory / 과정 품질 — 100점

| 세부 기준 | 점수 |
|---|---:|
| Agent가 어떤 순서로 작업했는지 남음 | 20 |
| 탐색 → 구현 → 검증 흐름이 자연스러움 | 20 |

| 최종 결과뿐 아니라 과정 evidence가 있음 | 15 |

| 세부 기준 | 점수 |
