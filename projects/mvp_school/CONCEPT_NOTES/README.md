# CONCEPT_NOTES/README.md

## 1. Purpose

`CONCEPT_NOTES/` stores reusable concepts that appear across MVPs.

A concept note explains how MVP School uses a concept. It should not become a governance pack or an enterprise methodology document.

## 2. When to create a concept note

Create a concept note when the same idea repeatedly affects scope, evidence, local handoff, or audit judgment.

Examples:

```text
THIN_ORCHESTRATOR.md
SOURCE_TRACEABILITY.md
EVIDENCE_TRUTHFULNESS.md
LOCAL_FIRST_RAG.md
AGENT_WORKFLOW.md
```

## 3. Concept note template

```text
# Concept Note: <Concept Name>

## Why this concept exists
## Meaning in MVP School
## When to use
## When not to use
## Overengineering signals
## Example
## Rejected example
## Related files
```

## 4. Boundary rule

A concept note should be short and practical.

If it starts adding scorecards, schemas, golden cases, governance matrices, or broad taxonomies, split it or reject the expansion.
